# Reglas permanentes
- Objetivo: demo dental profesional para vender webs a negocios de Paraguay, orientada a WhatsApp.
- Stack: Next.js App Router, TypeScript, Tailwind, npm y Git. Código simple, mantenible y responsive; reutilizar componentes cuando aporte valor.
- Evitar dependencias innecesarias y cambios de tecnología sin razón fuerte. No usar servicios pagos ni publicar en GitHub sin consultar. Secretos en .env.local ignorado.
- Clínica ficticia: no copiar marcas/material protegido ni presentar testimonios o credenciales inventados como reales.
- Verificar solo lo necesario según el cambio; no ejecutar siempre lint + build + navegador + responsive. Auditorías completas en hitos importantes.
- Explicar brevemente decisiones relevantes. Trabajar sobre archivos; no rehacer código funcional ni implementar mejoras opcionales fuera del alcance.
- Documentación y respuestas muy breves; actualizar documentos solo ante cambios importantes. Commits cortos en hitos razonables.
- No generar nuevos recursos visuales. Pedir al propietario la imagen con descripción, proporción y resolución; usar placeholders mientras tanto. Conservar la imagen actual autorizada.
- docs/DESIGN.md es la referencia visual oficial. No leer ni usar el DESIGN.md original de Apple salvo petición explícita.

Consultar según necesidad, nunca todos por rutina: AGENTS.md = reglas permanentes; docs/STATUS.md = estado; docs/DESIGN.md = tareas visuales; docs/PROJECT.md = alcance; docs/DECISIONS.md = decisiones previas relevantes.
